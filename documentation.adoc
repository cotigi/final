== Introduction

In this project we documented the network infrastructure 
of a package delivery company called BitBox. Like https://gls-group.com/HU/hu/home/[GLS]
and https://www.foxpost.hu/[FOXPOST], this company delivers to 
package lockers.

There are three sites:

Headquarters:: This location is where the company handles acounting and development.
Remote Package Storage:: This location is for long term package storage.
Package Center:: This location houses the packages and the company webserver, while also handling customer service
and in person package pick up.

== Project Management

=== Task Tracking
The task are tracked using https://trello.com/[Trello] with 
each task being assigned to one of three lists.

- *Todo*
- *In Progress*
- *Under Review*
- *Done*

The task naming convention is: *<category>: <topic>*

These categories are:

- *Documentation*
- *Programming*
- *Network*
- *Linux server*
- *Windows server*

==== Automations

===== Labeling

- When a new task is created in the Todo list, this automation
labels the task depending on the category mentioned at the start
of the task name.

- When a task is dragged into the Done list the Done label
is automatically assigned.

===== miscellaneous

- When dragging a task from Todo to In Progress,
it automatically assigns the said person to the task.

=== Documentation
The documentation is written in https://asciidoctor.org/[Asciidoctor]
and converted into PDF. This document is stored on https://github.com/[Github]
for easier teamwork and version control.

Every addition to the documentation is a new branch that has the 
following naming convention:

- *Networking:* network/<site>/<topic>
- *Programming:* prog/<topic>
- *Server:* server/<OS>/<topic>
- *Documentation:* docs/<topic>

When an addition is completed the person assigned to the task has to issue
a pull-request and the other party has to authorize it.
The main branch is protected and thus people can't push directly.

==== Github Actions

There is one workflow that is responsible for converting the 
Asciidoctor file to a PDF file for every branch on push and or pull requests.
This PDF file is uploaded as an artifact and can be downloaded in a zip file.
In the case of the main branch there is an additional feature 
that places the generated PDF file into the latest release.

=== Remote Access Policy

Remote access is achieved through the SSH protocol,
available on all available VTY lines on the given device, using
the default AAA configuration.

SSH is configured with the following parameters:

.SSH Parameters
[cols="1h,1",options="header"]

|Parameter

|Version
|2

|Key Modulus
|2048

|2

|Timeout
|30sec
|===

NOTE: Only the MANAGEMENT Vlan and the like (in the case of the Package Center site)
can access the vty lines. This is controlled by the `SSH` ACL placed on all
vty lines inward. For further information, refer to <<hq_ssh, HQ SSH>> and
<<pc_ssh, Package Cetner SSH>>

=== Port-security Policies

==== General

.Port-security Policy
[cols="3,^.^1",options="header"]
|===
|Policy 
|Upon Violation

|All connections leading to host devices must
allow atmost 2 MAC addresses
|Restrict

|All connections leading to printers or access points 
must allow atmost 1 MAC address with the sticky setting
.2+.^|Shutdown

|All connections leading to servers must
allow atmost 1 static MAC address

|All unused interfaces must be shutdown and
placedinto the TRASH Vlan
|Null
|===

All access interfaces must be configured with an
aging time of 5 minutes.

==== Dot1x

All switch interfaces connecting to a
PC, laptop or server must use Dot1x port authentication
through the given AAA RADIUS server.

==== IP Source Guard

* IP source guard must be configured on all switches and 
multi-layer switches with connections to end devices.

* All printer and servers must be statically configured
with it's given MAC and IP address.

NOTE: For further information, refer to 
<<hq_ip_sg, HQ IP Source Guard>> and
<<pc_ip_sg, Package Center IP Source Guard>>

=== DHCP Snooping Policy

DHCP snooping must me configured on all switches globally with
a rate limit of `20` on untrusted interfaces.

NOTE: For further information, refer to 
<<hq_dhcp_snooping, HQ DHCP Snooping>> and 
<<pc_dhcp_snooping, Package Center DHCP Snooping>>

=== Dynamic ARP Inspection Policy

All interfaces leading to host, printer or server devices, 
should be treated as, untrusted (this applies to unused interfaces too).

Interfaces leading to other network devies should be treated as trusted.

ARP packets must be validated through the source and destination
MAC addresses. This is achieved with the following command:

.ARP Inspection
[source]
----
ip arp inspection validate src-mac dst-mac
----

NOTE: For further information, refer to 
<<hq_arp_inspection, HQ ARP Inspection>> and 
<<pc_arp_inspection, Package Center ARP Inspection>>

=== Duplex Connection Policy

As all of the devices are IEEE 802.3u/ab compliant,
all interfaces are set to `auto`, as industry standard.

NOTE: IEEE 802.3u defines FastEthernet, while IEEE 802.3ab defines GigabitEthernet

=== Miscellaneous Policies

. All network devices/servers must be configured with the correct hostname
stated in the documentation, found at the given site's topology section.

. All network devices must be configured with `no ip domain-lookup`
to avoid accidental DNS lookup while configuring the given device.

. All switch and multi-layer switch interfaces (in switch-port mode)
must be configured with `switchport nonegotiation`.

. All network devices must be configured with `service password-encryption`.

. All network devices must be configured with `no cdp run`.

===== SSH

All network devices serving SSH, must have an ACL
configured so that only the `MANAGEMENT` Vlan can 
connect to the VTY line.

This is achieved with the following ACL

.SSH Access
[source]
----
ip access-list standard SSH
    permit 10.1.255.0 0.0.0.31
----

This ACL must be applied onto all the VTY lines for all incoming messages.

==== Access List

[[pc_ssh]]
===== SSH

All network devices serving SSH, must have an ACL
configured so that only the `MANAGEMENT` Vlan can 
connect to the VTY line.

The Package Center site is split into three
`MANAGEMENT` Vlans due to seperate broadcast domains,
so the ACL will accept the traffic if it is from
any of the three `MANAGEMENT` Vlans.

.SSH Access
[source]
----
ip access-list standard SSH
    permit 10.2.255.0 0.0.0.255
----

NOTE: This ACL must be applied onto all the VTY 
lines for all incoming messages.

===== DMZ

The following ACL is configured to allow outside requests
to enter the DMZ, and thus the the `Public Linux` server.

.Inward Access
[[source]]
----
access-list OUTSIDE-IN extended permit object-group DMZ-SERVICES any object DMZ-PUBLIC-IP
access-list OUTSIDE-IN extended permit object-group DMZ-SERVICES any object DMZ-NETWORK-IPV6
----

NOTE: For further information regarding these objects,
refer to <<pc_service_objects>> and <<pc_network_objects>>.

===== VPN

The following ACL is configured to identify, which packets
should be routed within the VPN tunnel.

.VPN Traffic
[source]
----
access-list VPN-TRAFFIC extended permit ip object LOCAL object REMOTE
----

NOTE: For further information regarding these objects,
refer to <<pc_network_objects>>.

===== Policy Map

The default policy map is additionally configured to inspect
HTTP traffic as well.

Thus the default policy map will be the following:

.Policy Map
[source]
----
policy-map global_policy
 class inspection_default
  inspect dns preset_dns_map
  inspect ftp 
  inspect http 
  inspect tftp
----

===== NAT

====== PAT

PAT was set up for the zones, `INSIDE1` and `INSIDE2`.
The network objects responsible for them are `LAN1` and `LAN2`.

These two PAT configurations are used by the whole network
across two different uplinks (This is why the same configuration
is duplicated), and so they use the same address, which is `12.12.12.2`.

====== SNAT

SNAT is set up specifically for the `DMZ`, with the 
responsible network object being named `DMZ-NETWORK`.

The server's address (`10.2.250.2`) is being staticly 
translated to `12.12.12.3`

def read_devices():
    """Read all the device informations out into a dictionary.
    Returns: Dict containing the names and ip addresses
    """

    devices = []
    file = open('resources/devices.txt', 'r') 

    lines = file.read().splitlines()

    for line in lines:
        location, name, ip = line.split(',')

        device = {
            "location": location,
            "name": name,
            "ip": ip,
        }

        devices.append(device)

    file.close()

    return devices

"""Network device connection and configuration handling."""

from netmiko.exceptions import NetmikoTimeoutException
from ..resources import resources
from ..files import log

import os
from netmiko import ConnectHandler

async def save_to_tftp(hostname, ip):
    device = {
            "device_type": "cisco_ios",
            "host": ip,
            "username": resources.user["username"],
            "password": resources.user["password"],
            "secret": resources.enable_password,
            "disabled_algorithms": {
                "kex": [],
                "keys": [],
            },
            "ssh_config_file": "~/Projects/final/necop/resources/ssh"
    }

    try:
        conn = ConnectHandler(**device)
    except NetmikoTimeoutException:
        return (False, "Null")

    conn.enable()

    response = conn.send_command_timing(
        command_string="copy running-config tftp:",
        strip_command=False,
        strip_prompt=False
    )

    log(str(response))

    if "Address or name of remote host" in response:
        response = conn.send_command_timing(
            command_string=resources.tftp_server,
            strip_command=False,
            strip_prompt=False
        )

    log(str(response))

    if "Destination filename" in response:
        response = conn.send_command_timing(
            command_string=f"{hostname.lower()}-confg",
            strip_command=False,
            strip_prompt=False,
            last_read=5.0,
            read_timeout=120.0
        )
    log(str(response))

    conn.disconnect()

    if "OK" in response:
        bytes_uploaded = str(response)\
                            .splitlines()[1]\
                            .lstrip("[")\
                            .rstrip("]")\
                            .split("-")[1]\
                            .rstrip("bytes")\
                            .strip()

        return (True, bytes_uploaded)
    log(str(response))

    return (False, "Null")

async def is_up(count, host):
    response = os.system(f"ping -c {count} {host} >/dev/null")

    return not bool(response)

            bytes_label.update(bytes_str+"B")
            bytes_label.set_classes("display-on")

            container.add_class("success-border")
        else:
            container.add_class("error-border")
