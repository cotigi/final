== Bevezetés

Ez a Dokumentáció a BitBox csomagszállító cég hálózati 
és szerver infrastruktújáról szól.
Ez a cég, mint a https://gls-group.com/HU/hu/home/[GLS]
és https://www.foxpost.hu/[FOXPOST], egy csomagszállító cég.

Az alábbi telephelyek lettek kiépítve:

Headquarters:: Cég vezetési, bérszámlálási és fejlesztési telephely
Remote Package Storage:: Hosszú távú csomag tárolás és feldolgozás
Package Center:: Rövid távú csomag tárolás és átadás, illetve web szerver
futtatása és tárolása

== Projektmenedzsment

=== Feladat Követés
A feladatokat a https://trello.com/[Trello] oldalon követjük.
Minden feladat az alábbi négy listán kell hogy átmenjen:

- *Todo*
- *In Progress*
- *Under Review*
- *Done*

Feladatok elnevezési szabálya: *<category>: <topic>*

Kategóriák:

- *Documentation*
- *Programming*
- *Network*
- *Linux server*
- *Windows server*

image::images/trello.png[align="center"]

==== Autómatizációk 

===== Bélyegezés

- Amikor egy új feladat a `TODO` listába kerül, ez az autómatizáió
meg bélyegezi az elöbb említett kategóriák alapján.

- Amikoe egy feladat átkerül a `DONE` listába, 
rákerül a Done bélyeg.

===== Egyéb

- Amikoe egy feladat átkerül az `In Progress` listába,
az adott személy automatikusan említve lesz a feladatban.

=== Dokumentáció
A dokumentáció https://asciidoctor.org/[Asciidoctor] leíró nyelvben
van írva, ami késöbb PDF formátumba lesz konvertálva. 
Ez a dokumentáció a https://github.com/[Github] felületen van 
tárolva, könnyebb csapatmunka és verzió követés érdekében.

Amikor egy új ág készül, az alábbi elnevezési szabályokat kell követni:

- *Hálózat:* network/<telephely>/<téma>
- *Programozás:* prog/<téma>
- *Szerver:* server/<OS>/<téma>
- *Dokumentáció:* docs/<téma>

Amikor egy feladat kész van, az adott személy létrehoz egy 
pull-requestet és a másik személynek ezt jóvá kell hagynia.

A main ág védett állapotvan van, így nem lehet direkt módosítani.

image::images/git-tree.png[align="center"]

==== Github Actions

Egy workflow létezik a repository-ban. Ez a workflow az asciidoctor
fájl-t, PDF-re konvertálja és a main ág esetében ez a PDF fájl kikerül
a latest release fül alá.

image::images/git-actions.png[align="center"]

=== Dynamic ARP Inspection Szabályzat

. Minden vég eszközhöz csatlakozó port nem megbízottként kell
hogy legyen tekintve (ez a nem használt portokra is igaz).

. Minden hálózati eszközhöz csatlakozó port megbízott

. ARP csomagokat validálni kell a forrás és cél MAC cím, illetve 
az IP cím alapján

.ARP Inspection
[source]
----
ip arp inspection validate src-mac dst-mac ip
----

NOTE: További információért, lásd
<<hq_arp_inspection, HQ ARP Inspection>> és
<<pc_arp_inspection, Package Center ARP Inspection>>

=== Egyébb Szabályzatok 

. Minden hálózati eszközt és szervert el kell látni az 
topológiában említett névvel.

. Minden hálózati eszközt el kell látni a `no ip domain-lookup`
parancsal.

. Minden switch és multi-layer switch portot el kell látni a `switchport nonegotiation`
parancsal.

. Minden hálózati eszközt el kell látni a `service password-encryption`
parancsal.

. Minden hálózati eszközt el kell látni a `no cdp run` parancsal.

. Minden switch portot el kell látni a `duplex auto` parancsal.

. Minden ASA eszközt csak konzolos módon szabad konfigurálni.

==== Access List

[[hq_ssh]]
===== SSH

Minden hálózati eszköznek, ami SSH-t biztosít, tartalmaznia kell
egy ACL-t ami csak az adott `MANAGEMENT` vlan-t engedi be a VTY 
vonalokra.

Ez az alábbi konfigurációval van elérve:

.SSH Hozzáférés
[source]
----
ip access-list standard SSH
    permit 10.1.255.0 0.0.0.31
----

NOTE: A fent említett ACL-t minden VTY vonalon a befelé tekintő
irányba, be kell konfigurálni.

===== VPN

A következő ACL a VPN csomagok felismerésére van konfigurálva

.VPN Csomag Felismerés
[source]
----
access-list VPN-TRAFFIC extended permit ip object LOCAL object REMOTE
----

NOTE: További információért a hálózati objektumokkal kapcsolatban,
lásd <<hq_network_objects>>

===== Befelé Irányuló Csomagok

Az alábbi ACL beengedi a VPN csomagokat és minden mást tilt.

[source]
----
access-list OUTSIDE-IN extended permit ip object REMOTE object LOCAL
----

Ez az ACL az `OUTSIDE` zónán kell hogy belegyen állítva.

[source]
----
access-group OUTSIDE-IN in interface OUTSIDE
----

===== SSH

Minden hálózati eszköznek, ami SSH-t biztosít, tartalmaznia kell
egy ACL-t ami csak az adott `MANAGEMENT` vlan-t engedi be a VTY
vonalokra.

A Package Center telephely három `MANAGEMENT` vlan-ra van bontva
mert a rétegek között különböző broadcast domain van.

.SSH Hozzáférés
[source]
----
ip access-list standard SSH
    permit 10.2.255.0 0.0.0.255
----

NOTE: A fent említett ACL-t minden VTY vonalon a befelé tekintő
irányba, be kell konfigurálni.

===== Befelé Irányuló Csomagok

Az alábbi ACL beengedi a VPN csomagokat, illetve a `Public Linux`-nak
címzett IPv4 és IPv6, HTTP és HTTPS csomagokat.

[[source]]
----
access-list OUTSIDE-IN extended permit object-group DMZ-SERVICES any object DMZ-PUBLIC-IP
access-list OUTSIDE-IN extended permit object-group DMZ-SERVICES any object DMZ-NETWORK-IPV6
access-list OUTSIDE-IN extended permit ip object REMOTE object LOCAL
----

NOTE: További információért az objektumokkal kapcsolatban,
lásd <<pc_service_objects>> és <<pc_network_objects>>.

Ez az ACL az `OUTSIDE` zónán kell hogy belegyen állítva.

[source]
----
access-group OUTSIDE-IN in interface OUTSIDE
----

=== Eszköz Válaszok
Minden gombnak négy statusza van amik szín alapján jelzik
a művelet állapotát, ezek:

- *Szürke*: Alapértelmezett
- *Narancs*: Tölt
- *Zöld*: Sikeres
- *Piros*: Sikertelen

NOTE: A művelet folyamata közben megjelenik ez töltést
jelző indikátor

A felület két tab-ra van felbontva, melyeket az alábbi sekciókban lehet
megtekinteni:

A `Devices` felületen az eszközök elérhetőségét lehet tesztelni

TFTP szerverre.

==== Válaszok
Az eddig kifejezett állapotokon felül (<<device_response>>),
a `TFTP` felületen, ha a művelet sikeresen lefutott, akkor az írt byte-ok
mennyiségét is kiírja a zöld jelzésen felül.

Eszközöket a `resources/devices.txt` fájlban lehet regisztrálni,
egy `,`-vel elválasztva.

- *Lokáció*
- *Hostnév*
- *IPv4 Cím*

*Format:* `<Lokáció>,<Hostnév>,<IPv4 Cím>`

"""Responsable for data storage to avoid unnecessary read operations."""

from . import files

class Resources:
    def __init__(
            self, 
            user = {
                "username": "AAAadmin",
                "password": "AAAadminpa55",
            },
            enable_password = "enpa55"
        ):

        self.update_devices()
        self.user = user
        self.enable_password = enable_password
        self.tftp_server = "10.1.50.5"

    def update_devices(self):
        """Calls the file reader from the files module."""
        self.devices = files.read_devices()

    def gen_conn_infos(self):
        """Generates the necessary connection information and returns it."""
        conn_infos = []

        for device in self.devices:
            conn_infos.append({
                "general_info": device,
                "thread_info": {
                    "device_type": "cisco_ios",
                    "host": device["ip"],
                    "username": self.user["username"],
                    "password": self.user["password"]
                }
            })

        return conn_infos

    def update_user(self, username, password):
        """Updates the user."""
        self.user["username"] = username
        self.user["password"] = password

    def update_enable_password(self, enable_password):
        """Updates the enable password."""
        self.enable_password = enable_password

resources = Resources()

    Returns: Dict containing the names and ip addresses
    """

    devices = []
    file = open('resources/devices.txt', 'r') 

    lines = file.read().splitlines()

    for line in lines:
        location, name, ip = line.split(',')

        device = {
            "location": location,
            "name": name,
            "ip": ip,
        }

        devices.append(device)

    file.close()

    return devices

"""Network device connection and configuration handling."""

from netmiko.exceptions import NetmikoTimeoutException
from ..resources import resources

import os
from netmiko import ConnectHandler

async def save_to_tftp(hostname, ip):
    device = {
            "device_type": "cisco_ios",
            "host": ip,
            "username": resources.user["username"],
            "password": resources.user["password"],
            "secret": resources.enable_password
    }

    try:
        conn = ConnectHandler(**device)
    except NetmikoTimeoutException:
        return (False, "Null")

    conn.enable()

    response = conn.send_command_timing(
        command_string="copy running-config tftp:",
        strip_command=False,
        strip_prompt=False
    )

    if "Address or name of remote host" in response:
        response = conn.send_command_timing(
            command_string=resources.tftp_server,
            strip_command=False,
            strip_prompt=False
        )

    if "Destination filename" in response:
        response = conn.send_command_timing(
            command_string=f"{hostname.lower()}-confg",
            strip_command=False,
            strip_prompt=False,
            last_read=5.0,
            read_timeout=120.0
        )

    conn.disconnect()

    if "!" in response:
        bytes_uploaded = str(response)\
                            .splitlines()[2]\
                            .split()[0]

        return (True, bytes_uploaded)

    return (False, "Null")

async def is_up(count, host):
    response = os.system(f"ping -c {count} {host} >/dev/null")

    return not bool(response)
